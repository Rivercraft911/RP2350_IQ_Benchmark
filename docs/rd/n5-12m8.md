# N5: cyclic 8PSK at 12.8 Msym/s, SYS128

**Device result (coordinator, 2026-10-16):** `bench5quad8` ran 60 s clean at 12.8 and 6.4 Msym/s,
priorities 0 and 13, supervision 0.8%; inverted clock detected. See
[results](../../results/n5-12m8/2026-10-16/README.md).

**The pulse model passes; the opt-in cyclic engine builds and passes native validation. Device throughput is unmeasured.** `bench5quad8` emits five samples/symbol using a 128 KiB table, four SRAM-fed DMA chains and four writers. At SYS128/cpw1 its calculated rate is 12.8 Msym/s, with 64 MSPS per DAC axis. cpw2 is the 6.4-Msym/s control. No attached Pico, serial port, flashing or device-management command was used. Existing measurement evidence and Git metadata were not changed; no commits were made.

Work is on `rd/n5-12m8`, based on `a04e6ba3a7f7f6303b5ed342ded2ad06506fc20b`. The unchanged N4 commands remain available in the same experiment image. Normal builds and autonomous `pvflight` exclude this command and table.

## Pulse gate and packing

The selected pulse is a symmetric, 35-tap, L7/N5 approximation to the α=0.20 RRC response. It uses the same mask-constrained receiver-sidelobe objective as B1, adapted correctly for an odd tap count: 17 mirrored pairs plus one center coefficient. It is not an assertion that truncating a textbook RRC passes the mask. `host/design_iq5pulse.py` reproduces the design from repository mask data using 18 variables, 6,001 uniform frequency points plus exact mask knots, held-DAC response, a unit ideal-RRC receiver main sample and an LP outer approximation to the RMS sidelobe norm. The selected design requested 0.10 dB mask reserve and 2 dB additional far reserve; the LP converged in 20 iterations, norm-bound gap 1.27×10⁻⁸. Reproduction yields all 35 frozen Q8 taps exactly. The final rounded table, rather than the LP grid, determines admission.

`iq5hist_build()` computes each sample as

```
q8 = floor((sum(tap_q8[age,phase] * level_q30[code[age]]) + 3388*2^31)
           / (3388*2^32))
```

The four levels are `[992008094, -410903207, 410903207, -992008094]`, as in B1/B4. Rounding occurs once after the complete FIR sum, with ties toward positive infinity and correct floor division for negative values. The newest two-bit coordinate code remains low in the 14-bit history key. Each row has chronological samples 0–3 in the four bytes of word 0, sample 4 in byte 0 of word 1, and three zero padding bytes. There are 16,384 rows / 81,920 samples / 131,072 bytes. CRC32 is **`0xa299c7c1`** (2727987137); Q8 coefficient SHA-256 is `8050cbc2693c14033cb585dc26cc29e4f2726911908cd9c3f0a491fb27111b4b`.

The exhaustive peak is ±127. D13..D6 carry the signed byte; D5..D0 and D15 remain zero, and GPIO14 carries IQ_FLAG. The signed AFE code is exactly `64*q8`, with peak ±8128 and 0.0671 dB headroom relative to 8191. This requires the AFE's two's-complement input mode (local SLOS789C CONFIG1, p18, checked). Gain is `4096/3388 = 1.20897285` relative to interpreting the same Q8 taps as a 14-bit table; it is not an amplitude comparison to the different N4 pulse. No AFE registers are programmed here.

The certificate uses the same EN 302 307-1 V1.4.1 Annex A amplitude model as B1/B4. Annex A p37 and Table A.1 p38 were checked in the local source: α=0.20 mask points and the rectangular-input correction. Frequency is `fn=f/(Rs/2)`; mask power is interpolated in dB. Exact overlapping-history covariance gives the actual rounded iid four-level table PSD; an independent Walsh decomposition checks PSD probes and retains nonlinear quantization terms in receiver variance. The ideal hold contributes `sinc(fn/10)` in amplitude.

| Actual 8-bit N5 table | Upper margin | Lower margin | Far reserve above 40 dB | EVM incl. ISI/nonlinearity | MER |
|---|---:|---:|---:|---:|---:|
| Digital only | −1.992207 dB | +0.250000 dB | −1.992207 dB | 1.278752% | 37.864273 dB |
| Ideal held DAC | **+0.026629 dB** | **+0.214500 dB** | **+1.768508 dB** | **1.486896%** | **36.554391 dB** |

Continuous amplitude certification uses 1,048,586 frequencies including mask knots, and subtracts a global derivative bound times half the largest gap. Held upper/lower certified amplitude slacks are **7.802129×10⁻⁶ / 0.021997644**. The worst upper point is fn=1.49819183. Receiver integrations at 16,384 and 65,536 frequencies differ by only 2.54×10⁻⁹ EVM percentage points. Quantization error versus real constellation coordinates and the frozen taps is at most 0.499945691 byte LSB, below the 0.5000000642 bound. All five phase means are exactly zero.

| Packing considered | Row/table | Model outcome |
|---|---|---|
| Five signed 8-bit values + 24 pad bits | 2 words / 128 KiB | Selected; held continuous certificate passes |
| Five signed 6-bit values + 2 pad bits | 1 word / 64 KiB | Near-full-scale divisors 13704/13705/13706 fail held upper mask by 1.407–1.439 dB, near fn≈1.698; MER around 35.16 dB does not rescue the mask |
| Five 14-bit values in 16-bit slots | 3 words / 192 KiB | Exceeds borrowed 128 KiB arena; not implemented or spectrum-certified |

These are evaluated alternatives, not a proof that every possible six-bit pulse fails. Divisor 3386 gives positive sampled byte-mask reserve but fails the continuous certificate; 3387 passes with less certified slack than selected 3388. Larger requested LP mask reserves of 0.2–0.5 dB with the same extra far reserve were infeasible. No longer-span table was needed; L8 would multiply the row count by four.

Numeric outputs, tool versions, alternatives and design provenance are in [n5-model.json](n5-model.json). Scope is iid uniform coordinates, ideal held DAC and ideal α=0.20 RRC receiver. The certificate covers upper fn∈[0,6], lower [0,1.11], far [1.7,6]; at 12.8 Msym/s its upper endpoint is 38.4 MHz. It does not certify deterministic PLHEADER/pilot/coded-payload spectra, group delay, reconstruction images, physical AFE/RF response or a receiver decode. The small positive mask reserve is a model gate, not analog margin.

## Engine and timing budget

For `d=cpw`, one symbol occupies **10d SYS cycles**: five I and five Q bus slots. Thus `Rs=128e6/(10d)` and each alternating chain has a **20d-cycle row deadline**. GPIO28 remains high for I and low for Q; it toggles every bus slot, so its frequency and per-axis sample rate are `64/d MHz`. No clock or voltage is changed.

The selected graph is B5's four independent SRAM control/sample pairs, with the existing `iq4quad_build()` history traversal and an eight-byte row stride. It precomputes a cyclic 4096-symbol PRBS period into four deinterleaved 2048-pointer rings ordered I-even, Q-even, I-odd, Q-odd. The period tail supplies all preceding history, so startup and wrap introduce no FIR transient. Reusing the helper does not depend on N4: its inputs are L7 coordinate histories and row byte stride.

| Four-chain design at cpw1 | Measured loop basis | Deadline minus loop | DMA transfers/symbol | FASTPERI accesses/symbol | Port load off / capture on |
|---|---:|---:|---:|---:|---:|
| Selected: two-word rows, SRAM addresses | 16 cycles | **4 cycles** | 6 | 6 | **60% / 65.882%** |
| Two-word rows, four PIO producers | 18 cycles | 2 cycles | 6.25 | 8.25 | 82.5% / 88.382% |
| Rejected six-bit one-word SRAM rows | 11 cycles | 9 cycles | 4 | 4 | 40% / 45.882% |
| Rejected six-bit one-word PIO rows | 14 cycles | 6 cycles | 4.25 | 6.25 | 62.5% / 68.382% |

Loop figures are inherited **device measurements**, not new N5 measurements: [dmaloop](../../results/dmaloop/2026-10-15/README.md). At priority 0, the two-word SRAM result was 16–17 cycles, leaving 3–4 cycles; PIO was 18–19. cpw2 doubles deadlines and halves all utilization percentages, but does not imply the loop itself doubles. The measured sinks never back-pressured and addresses did not exercise this table's full access pattern. The N5 experiment must still measure arbitration and FIFO service.

Per symbol the SRAM graph has two pointer reads/trigger writes and four sample reads/FIFO writes. At cpw1 this is 76.8 M DMA transfers and FASTPERI accesses/s, plus 307.2 MB/s SRAM reads (102.4 pointers + 204.8 table). Stride-17 capture adds 7.5294 M port accesses/s and 30.1176 MB/s SRAM writes for about 544 µs per 4096-word capture. A PIO pointer transfer costs two port accesses, RX FIFO read and DMA trigger write; four duplicate full-history input streams add 0.25 source transfers/accesses per symbol. Its lower SRAM reads (217.6 MB/s) trade against higher port load and weaker handoff margin. Priority changes arbitration, not port capacity.

Each new writer has seven PIO words. The first four OUT8 samples loop on alternate slots; a separate fifth OUT8 is followed by OUT NULL24, then delayed SET/JMP instructions. Only OUT PINS changes data/IQ_FLAG. Initial PCs `[0,1,4,6]`, X `[3,4,0,0]` give first outputs at slots `[0,1,10,11]`; each chain repeats every 20 slots. The odd writers bypass the padding discard during startup. Padding is discarded even if its bytes are nonzero. RP2350 §11.5.4.2 p910 was checked locally: non-OUT cycles allow autopull, while entering an OUT already exhausted stalls it for a pull. The intervening instructions permit prefetch without shifting the bus schedule. The opcode model covers these retry semantics.

Conservative no-refill runway from a preloaded OSR plus seven remaining FIFO words is **80d SYS cycles**; a full FIFO plus OSR gives **88d**. This is deterministic packed-writer runway, not a latency guarantee. It exceeds the 20d row interval but cannot compensate a sustained service deficit.

| Implemented resources | Allocation |
|---|---|
| Writers | PIO2: 4 SMs, 14 instruction words shared between even/odd writers |
| GPIO28 DDR clock | PIO0: 1 SM, 2 words |
| GPIO capture | PIO1: 1 SM, 3 words |
| Total | **6/12 SMs, 9/16 DMA channels, 19 words across the three independent instruction memories** |
| DMA | Four control/sample pairs plus one capture channel |
| CPU | No sample arithmetic or address generation during output; core 1 idle; core 0 polls faults every 128 µs, maximum allowed gap 256 µs |

The hypothetical cyclic PIO-source graph would require ten SMs/thirteen DMAs including clock/capture. An N5 producer needs the L7 history and an eight-byte offset, not B6's existing four-byte address shift. It is not implemented here. B6's current live grant service also reserves core 1; its successful waveform runs cannot establish two-core FEC integration. SRAM cyclic pointers are a benchmark source; generating 25.6 M new pointers/s for live data is not treated as free.

## SRAM and CPU/FEC implications

No new static arena is allocated. The command borrows the existing 128 KiB output ring for the table, 32 KiB input buffer for pointers, and 16 KiB of capture storage. Setup temporarily uses 2 KiB of the capture buffer for packed symbols. Startup refuses incompatible resources or an owned output engine; stop checks claims, restores selectors and regenerates the original input PRBS only after cleanup succeeds. `quad_n5` consumes existing struct padding: the dual engine remains 0x278 bytes.

Final Release experiment linker-map addresses, unchanged from the baseline build:

| Object | Address / extent |
|---|---|
| N5 table (`ring_buf`) | `0x20000000`, 128 KiB |
| Four pointer rings (`in_buf`) | `0x20020000`, `0x20022000`, `0x20024000`, `0x20026000`, 8 KiB each |
| Dual-DMA state | `0x2003e780`, 0x278 bytes |
| `cap_buf` | `0x20051fac`, 56 KiB; first 16 KiB used by capture |
| Lower SRAM BSS end / reserved heap | `0x2003fbb0`; heap 0x400, leaving **80 bytes** before `0x20040000` |
| SRAM4–7 static end / core-0 stack | `0x2007efe8`; 24 bytes before the 4 KiB stack at `0x2007f000..0x20080000` |
| `dvbs2_transpose32` / core-1 stack | `0x20080498`, 0x134 bytes; stack `0x20080800..0x20081000` |

New setup/command code is in flash: `iq5hist_build` at `0x10026160` (0x2c4 bytes), `bench5quad8` at `0x100264a8` (0x80c bytes). No hot FEC code or data was moved. These addresses identify this build; future changes require a new map audit.

A normal 8PSK frame with pilots is 22,194 symbols. N5/cpw1 gives 1.73390625 ms/frame, **221,940 SYS cycles per on-air frame and 443,880 per assigned alternate frame per core**, before supervision. cpw2 gives 887,760 cycles per assigned frame. A 300k-cycle kernel would consume 67.6% of the N5/cpw1 allocation, as a planning estimate. This image has no C5/C6/C7 changes: inherited C4 measurements instead put simultaneous 5/6 options-27 work around 403.5–413k cycles, consuming 90.9–93.0% and leaving only 30.9–40.4k before other work. Options31's simultaneous scratch-Y BCH case was around 495k and does not fit. These observations come from [ldpc-banks](../../results/ldpc-banks/2026-10-15/README.md), not an N5 run.

The new shaper issues **zero ARM instructions per symbol** after setup. The compiled pre-capture fault query executes about 45 ARM instructions including its wrapper; timer/counter and caller bookkeeping add several tens. Instruction accounting with [M33 timing notes](../rp2350-notes.md) suggests order 100–250 core cycles per 128-µs service, about 0.6–1.5% of a core before IRQ/bus delays; this is an estimate, not measured utilization or a hard bound. The command records actual supervision cycles when run. Its idle spin is excluded from the reported useful-work fraction. Host test durations are not M33 timing measurements.

Memory is a separate integration gate. The existing `c3fec` context begins at `ring_buf+16384`, exactly the upper half of the N5 table. ARM compile-only `sizeof` inspection gives **54,200 bytes** for its context and **19,312 bytes** per job in this image. Moving that entire context into the 57,344-byte capture arena would leave only 3,144 bytes, insufficient for this command's 16 KiB capture. The SRAM pointer rings also occupy the storage used for live packed codes. A complete transmitter therefore needs a new ownership/layout design and likely PIO producers; merely running these two commands together would corrupt storage.

Calculated 5/6 BB data capacity is `(53840−80)*12.8e6/22194 = 31.00514 Mb/s`, about 11.0% above the measured 27.94-Mb/s QPSK9/10 pipeline. Nominal width is `1.2*Rs = 15.36 MHz`. At cpw1 the first DAC image is **centered at 64 MHz**, with nominal nearest edge `64−0.6*12.8 = 56.32 MHz`; the 56-MHz figure is an edge, not an image center. No image attenuation was measured or certified. Existing 32-MHz PV-SPI emulation's approximately 30.8697-Mb/s ceiling is below even this BB capacity, before its separate ingress costs. These rates are potential capacity, not a completed transmitter result.

```sh

PICO_TOOLCHAIN_PATH="$HOME/.pico-sdk/toolchain/14_2_Rel1" \
cmake -S firmware -B firmware/build-exp -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DIQ4HIST_EXPERIMENT=ON -DCORE0_STACK_SRAM_HI=ON

python3 host/design_iq5pulse.py --out /tmp/n5-design.json
python3 host/test_iq5hist.py --spectrum
make check
```

Both firmware configurations build without new warnings. `make check` includes the new tests and all existing native/reference checks. No host timings are presented as device performance.

- `test_iq5hist.py` compiles production C with `-Wall -Wextra -Werror`, compares every row/sample to a separately written scalar FIR and vector reference, and checks capacity/guards, padding, signed bus mapping, four PRBS seeds and five publication block sizes.
- `test_quint_rows.py` executes actual firmware opcodes over 32 ring laps, both dividers/clock phases, nonzero padding and autopull retry/starvation; corrupt discard/start/X/threshold/dropped-word controls must fail. It compiles the actual new start API against native DMA/PIO fixtures, including admission, two-word transfer counts, DREQs, wrapping, injected startup failure and reset back to N4.
- `test_bench5quad.py` executes the production command with real table/source/pointer code and synthetic time/output. Both rates/priorities/phases, setup/CRC/pointer/output/capture/poll failures and failed cleanup are covered. Synthetic GPIO does not validate device output.
- `test_iq5quad_trial.py` validates the independent scalar-FIR GPIO reference and rejects N4 waveform/profile/rate, emitted padding, bit/order/clock errors, bad identities/CRCs, short captures and cleanup failures. Tests never instantiate an unmocked board.

Experiment UF2 SHA-256 is `75aa6864ee1bfcb5b3b5669ffd11dd7e247500b442efb22ce693f9dacf94479e`; ELF SHA-256 is `da3f7e020ab4ed7807f3b7e5b6cec0f7e18e1cd286dcc2e42b3d566810706d1b`. ## Remaining risks and intended commits

The digital gate still needs the short/inverted/60-s measurements above, particularly capture at priority0 with the two-word row loop. The native opcode model assumes identical divider phases and does not establish PIO-to-pad latency or DAC setup/hold. Actual table bank access, USB/IRQ tails, rare stalls, clock skew, temperature and analog spectrum/EVM remain unmeasured. The four-cycle loop margin is inherited planning evidence. The mask reserve is small; the first image lies outside the certificate. Complete on-chip FEC and ingress additionally require new memory ownership, grant servicing and live cadence. None of those risks is counted as a positive result here.

Dead ends retained: tested six-bit quantization fails the far mask; 14-bit rows exceed the available arena; a longer history expands the table beyond the ring; the tested tighter same-span LP margins were infeasible. Four PIO producers are feasible on paper for cyclic output but spend more of FASTPERI and the loop margin; no N5 producer/live engine is claimed. Reusing C3's current table-tail storage with N5 would corrupt the waveform.
