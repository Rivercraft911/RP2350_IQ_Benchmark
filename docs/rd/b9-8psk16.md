# B9: complete on-chip GCS 8PSK 2/3 through the B6 waveform engine

**Implemented, native verified, and linked; device throughput is unmeasured.**
The opt-in experiment command `b9` connects memory GCS → BB scrambling → BCH →
LDPC → packed 8PSK/PL codes → four alternate-row PIO producers → four DMA row
loops → four OUT8 writers and the GPIO28 DDR clock. There is no CPU sample or
row-address calculation. Both cores perform FEC; core 0 services finite input
DMA completions through a high-priority interrupt. This work does not establish
an integrated 16-Msym/s positive result until the coordinator runs the matrix
below. No attached Pico, serial port, flashing tool, or Git metadata was touched.
Existing results evidence was not edited.

## Command and implementation

```
b9 cpw ms invert prio slow_us options
```

Defaults are `1 3000 0 13 0 251`. Only SYS128, cpw 1/2, normal 8PSK 2/3,
pilots, Gold 0, options 0/251 are admitted. Other commands and the ordinary
startup retain their prior selections. The command exists only in
`IQ4HIST_EXPERIMENT=ON` iqbench; pvflight does not include it.

- [bench_b9.c](../../firmware/src/bench_b9.c) reuses C3's actual sliced jobs,
  C8 mask 251, B6's PIO producer program, and B5/B6's atomic writer/clock start.
  The source is C3's deterministic memory GCS: chronological payload byte `j`
  is `(29*j+7)&255`, with the GCS BBHEADER. This is a complete on-chip digital
  transmitter from an in-memory source, not an external ingress demonstration.
- Regular service uses `iq4prod_dma_poll_irq`, a three-word result, rather
  than copying the full diagnostic structure at 31,250 polls/s. The four
  completed cursors are individually monotonic 32-bit values: if an IRQ
  interrupts their reads, the resulting minimum is conservative. Full snapshots
  remain in publication and final diagnostics.
- Two frames are encoded and published before output starts. The two workers
  then begin their next same-parity frames as soon as their previous frames
  publish. GCS, BCH and LDPC use private job storage and may run ahead.
- Before **every MAP slice**, the scheduler requires
  `ceil((frame_index+1)*22194/16) - min(completed[4]) <= 4096`.
  The mapper begin functions only initialize state; output stores start in its
  step function. This reserves the entire next frame interval, including its
  partial tail, before its first ring store. The initial two frames need only
  2,775 groups of credit and fit the 4,096-group ring.
- Frames publish in order. `c3_job_publish` merges the deferred first word with
  the previous frame's carry. A DMB precedes release of
  `floor(published_frames*22194/16)` paired-axis groups to DMA. A partial group
  is never a grant. Frames are not padded independently; continuous PL and FIR
  history cross every frame boundary.
- Six zero **codes** per axis seed the PIO histories (`previous_words=[0,0]`),
  matching B6's runtime startup. This is distinct from zero-amplitude samples.
- Supervision requests a 32-µs cadence and faults above 128 µs. It checks input
  and output faults, publishes ordered frames, updates retired credit, wakes a
  credit-blocked core 1 with SEV, releases jobs and starts a sparse capture.
  Core 1 uses WFE while idle or waiting for credit.
- On stop, writers/clock stop first, then producer DMAs, then core 1 joins.
  Only after the DMA claims have been released does an untimed drain finish
  the two admitted jobs, without releasing new jobs. This makes the final
  `code_crc` reproducible. `stream_frames/groups` record the live DMA-visible
  prefix; `published_frames/groups` include the subsequent drain. Capture is
  checked against the live stream, not against this drain.

`elapsed_us` covers the output loop. `accounting_elapsed_us` extends through
stop/join, before the deterministic drain. `timed_busy_cycles` excludes prefill
and drain; the reported core busy fractions and `supervise_busy` use the latter
accounting interval. Total `busy_cycles`, stage cycles, maxima and frame counts
include prefill/drain so they can be reconciled with the final ring reference.
IRQ time that interrupts a measured work/service interval is already charged
there: do not add `grant_irq_cycles` again. IRQ body counters exclude exception
entry/exit and their final statistic stores; an IRQ during the excluded idle
wait is not included in the work fraction. Treat the fractions as diagnostic
work accounting, not an exact processor-reservation measurement.

## Finite grants without a reserved core

[iq4prod_dma.c](../../firmware/src/iq4prod_dma.c) adds
`iq4prod_dma_prepare_irq`. The original cyclic and core-1 worker entry points
remain available. The new path claims an otherwise unused core-0 DMA IRQ2/3,
sets priority 0, and restores its handler, enables and priority on release.
The current core-1 task loop never enables DMA IRQ2/3. A future integration
must preserve that condition; core 0 cannot inspect core 1's NVIC enable state
through its ordinary SDK calls.

Each of four input channels remains a finite normal-mode transfer. After BUSY
clears, its preceding grant has retired; only then does its completed cursor
advance. The handler rearms that channel with
`min(512, published - previously_granted)` words. No transfer crosses the
published prefix. A short final grant preserves the remaining frame runway
instead of discarding up to 511 published groups. Publication explicitly kicks
idle channels that have no further completion interrupt pending. SRAM code and
paired data stores precede grant publication.

A delayed interrupt can stall output; it cannot read an unpublished group or
replay stale ring contents. Producer TXSTALL is sticky SOURCE_EMPTY and inhibits
further grants. Foreground progress also reads both producer FDEBUG registers:
terminal starvation must be detected even when no further completion IRQ will
arrive. DMA and illegal FIFO faults have separate flags. The command reports
all four granted/completed cursors, minimum reuse credit, IRQ calls/body cycles,
maximum body cycles, input/output errors, resource restoration and capture CRC.
A body maximum is **not completion-to-entry latency**.

### Counted resources and traffic

At cpw `d`, a symbol takes `8d` SYS cycles. SYS128 gives 16/8 Msym/s at d1/d2,
64/32 MSPS per axis, and 64/32 MHz GPIO28. One 22,194-symbol pilot frame takes
177,552d cycles; an alternate-frame worker has **355,104d cycles** per frame.
At d1 the payload is 42,960 bits/frame, or **30.97053 Mb/s**.

The unchanged B6 graph uses four input + four control + four sample + one
capture DMA = **13/16 channels**. It uses 4 producers + 4 writers + DDR clock +
capture = **10/12 SMs**. PIO0 has three producers plus clock (13 instructions),
PIO1 one producer plus capture (14), PIO2 four writers (8). There is one DMA
subscriber per DREQ.

| Both axes, per symbol | DMA read/write pairs | FASTPERI accesses |
|---|---:|---:|
| Two SRAM sample rows → writers | 2 | 2 |
| Two producer RX addresses → DMA trigger registers | 2 | 4 |
| Four packed code readers, one word per 16 symbols | 0.25 | 0.25 |
| Total | 4.25 | 6.25 |
| Additional stride-17 pins32 capture | 8/17 | 8/17 |

At d1 this is 68 M DMA pairs/s and 100 M FASTPERI accesses/s; during capture,
75.529 M pairs/s and 107.529 M accesses/s: **59.01% DMA / 84.01% FASTPERI** of
the ideal collective ceilings. SRAM sample/source reads total 144 MB/s; capture
adds 30.118 MB/s writes for about 544 µs. These are aggregate counts, not bank
latency guarantees. d2 halves waveform/capture utilization.

A completion service requests 1 IRQ acknowledgement + 2 FDEBUG reads + 4 CTRL
reads + 0..4 rearm writes = **7..11 FASTPERI accesses**, no extra DMA channel.
At most three grants per stream per frame gives approximately 8,651 completions/s
at d1, plus up to 721 foreground publication kicks/s. Fully independent single
completions plus kicks request about 74.3k accesses/s (0.0581% of SYS128).
Terminal-stall polling adds 2 reads/32 µs = 62.5k/s (0.0488%). Their combined
**0.107%** replaces B6's approximately 6.35% spin-worker port envelope. Counting
the existing output fault polls too gives CPU port demand of approximately
0.1558% before capture, 0.1802% after capture has started, and 0.2046% while it
is active. Allowing one extra pending NVIC entry per foreground kick adds
0.00394% port demand; full diagnostic progress at publication adds 0.00113%.
Thus a conservative aggregate is approximately **78.286% without capture /
84.217% during capture**. Timer/APB traffic, USB and arbitration are additional;
these fractions are access counts, not measured bus occupancy.

The 376-byte `-Os` Thumb handler has approximately 149 executed instruction
slots for one rearm/three BUSY streams, 215 for four rearms, and 127 for an
all-BUSY publication kick. Using [rp2350-notes.md](../rp2350-notes.md), estimates
are 180–260 cycles for a single rearm and 250–350 for four, before contention,
exception entry/exit and final statistic stores. At the independent-completion
bound this is approximately **1.2–1.8% core 0**, plus about 0.1% for publication
kicks; coalescing reduces it. These are instruction-based estimates, not M33
measurements. Foreground scheduling/publication and changed SRAM traffic must
also be measured. C8's prior 6.6% supervision and approximately 17% core-0
headroom are historical CPU-only measurements, not B9 measurements.

The narrow clean producer poll has approximately 75 Thumb instruction slots,
21 loads and 8 stores, with no memcpy. A word-beat/instruction model estimates
110–150 cycles/poll, **2.69–3.66% core 0** at 32 µs. Clean output fault checks
are approximately 46 slots before capture and 64 after capture completes,
estimated at 70–90 / 95–125 cycles. Together these recurring checks add about
**4.4–5.9% before capture / 5.0–6.7% after capture**. The active 544-µs capture
window adds a count-register check. LDM/STM timing is unverified in the project
notes; SRAM, XIP and FASTPERI stalls are excluded from these estimates.

Full diagnostic copies at publication estimate another 550–650 cycles/frame,
**0.31–0.37% core 0**, excluding the already counted IRQ kick. Admitted MAP
credit checks add about 19–24 instruction slots, 30–45 cycles per slice; C6
has 22 MAP slices/frame. Including the non-MAP stage test, allow approximately
**0.2–0.35% per core**. A pending NVIC entry after a foreground kick can call
an empty handler; allow 0.085–0.113% core 0 plus unverified exception timing.
Adding these estimates to C8's historical 82.7% core-0 duty gives roughly
**90–92%**, before changed placement/arbitration, IRQ entry/exit and credit-wait
latency. This is a budget comparison, not a B9 performance prediction.

[dmaloop](../../results/dmaloop/2026-10-15/README.md) measured a four-chain,
one-word PIO-pointer loop at approximately **14 cycles**, versus B9's **16-cycle
per-chain deadline** at d1 (32 at d2). The nominal margin remains two cycles.
Removing busy polling lowers average port demand but does not establish a
worst-case deadline: interrupt rearm bursts, FEC SRAM arbitration and capture
can still exhaust FIFO runway. Priority 0 and 13 are both required controls.

### Why the other grant approaches were not selected

- A 32-µs BUSY-clear poll cannot guarantee renewal. Four TX FIFO words plus an
  OSR hold at most 80 symbols, about 5 µs at d1; occupancy at actual completion
  can be lower. Larger grants reduce seam frequency, not the terminal deadline.
- One reload DMA per independent reader needs 17 channels with the existing
  capture. Dropping capture would fit 16 but prevent the required concurrent
  waveform check. Sharing a reload trigger has no four-reader completion
  barrier under independent backpressure.
- A read-address cursor is not a retirement proof. Wrapped DMA addressing does
  not provide the simple in-flight address adjustment assumed by some designs.
  B9 uses finite BUSY-cleared retirement instead.
- Releasing whole jobs only after 512-group retirement would delay frame 2 by
  roughly 512 µs and leave about 290k cycles before playback. C8's measured
  worst frame was 318.7k cycles. Deferring only MAP removes this avoidable delay
  while retaining the conservative finite cursor.
- The first integration copied the 144-byte diagnostic result every 32 µs.
  Its clean path is approximately 247 Thumb slots plus multiword transfers,
  estimated at 350–450 cycles/poll (8.5–11% core 0). The narrow poll replaces
  this avoidable cost; the full snapshot remains appropriate at frame rate.

The interrupt is the smallest change used here. Seamless renewal is a device
measurement gate, not a proved latency bound.

## SRAM and placement

The experiment image links with SDK2.2.0/GCC14.2.1. The actual ARM linker map,
`firmware/build-exp/iqbench.elf.map`, gives:

| Storage/code | Address | Bytes |
|---|---:|---:|
| Existing ring reservation | 0x20000000 | 131,072 |
| OUT8 table within ring | 0x20000000 | 65,536 |
| B9 context within ring tail | 0x20010000 | 58,744 |
| Gold arena | 0x200197f4 | 5,536 |
| C6 mapper table/code arena | 0x2001ad94 | 5,008 |
| C5 LDPC code arena | 0x2001c124 | 8,192 |
| Core-0 private BCH arena | 0x2001e124 | 512 |
| I/Q packed rings | 0x20020000 / 0x20024000 | 16,384 each |
| Existing link ring, not borrowed | 0x20028000 | 32,768 |
| Core-1 private BCH arena | 0x20051fac | 512 |
| Pins32 capture, `cap_buf+256` | 0x200523ac | 16,384 |
| IRQ code, scratchY | 0x20081898 | 376 |
| Preserved B6 core-1 worker | 0x20081a10 | 1,156 |
| Producer mutable state | 0x20081ea8 | 336 |

The B9 context ends at 0x2001e578, leaving **6,792 bytes in the borrowed tail**.
`cap_buf` is 57,344 bytes; the first 1 KiB is reserved from capture so capture
cannot overwrite executable BCH code. No new full frame, source, LUT or capture
array is statically allocated. Native context sizes differ because host pointers
are wider; use the ARM size above.

Global free space is much smaller than arena slack: **4 B lower SRAM** after the
1-KiB heap reservation, **24 B SRAM4–7** below the 4-KiB core-0 stack, **16 B
scratchX** before the 2-KiB core-1 stack, and **8 B scratchY**. Both builds must
be relinked after any edit. The handler initially compiled to 700 B at `-O3`
and overflowed scratchY; its opt-in `-Os` placement produces the 376-B body.
That failed placement is not a runtime result. Do not add static state casually.
The command's own Arm stack frame is 912 bytes (36 saved-register bytes + 876
local bytes), excluding callees, main dispatch and interrupt frames. Stack paint
on the coordinator's actual image remains required.

`stackcheck` formerly compared mutable producer state with flash alongside code,
which would falsely fail after B9. The linker now defines
`__scratch_y_code_end__=0x20081ea8` before the mutable tail; the total end remains
0x20081ff8 for allocation and paint bounds. Every executable instruction/literal
is still compared with flash. `test_stackcheck.py` checks mutable-tail changes,
first/last instruction corruption, the unchanged paint boundary and ordinary
full-bank comparison. Producer stop also latches late AHB errors before SDK
cleanup clears hardware flags, without advancing aborted partial grants.

## Native verification

Both builds and the full `make check` pass. The following do not access USB or
measure M33 speed:

```
make build
export PICO_SDK_PATH="$HOME/.pico-sdk/sdk/2.2.0"
export PICO_TOOLCHAIN_PATH="$HOME/.pico-sdk/toolchain/14_2_Rel1"
cmake -S firmware -B firmware/build-exp -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DIQ4HIST_EXPERIMENT=ON -DCORE0_STACK_SRAM_HI=ON
make build BUILD=firmware/build-exp
make check
```

- `test_b9_bench.py` compiles the actual command and encoder with native shims
  and `-Wall -Wextra -Werror`: five test methods, 22 command executions. It
  checks delayed independent readers, blocked MAP credit, ring seams, cpw1/2,
  options0/251, priority/inversion, slow-worker underrun, setup/output/capture
  faults, admission and restoration. Final ring CRCs equal the independent
  Python GCS/BCH/LDPC/PL reference.
- `test_iq4prod_irq.py` executes actual IRQ/progress/publication leaves over
  20 ring laps with independently delayed readers, short grants, idle kicks,
  unpublished-read/early-overwrite guards, terminal starvation without a new
  IRQ, DMA/FIFO errors and invalid publication. Existing B6 tests still run.
- `test_b9_trial.py` and `b9_trial.py --self-test` check the independent scalar
  chain through FIR and pins32 parsing. Ten tests cover frame seams, frame
  43,210, every bus bit, axis/parity swaps, inverted clock, stale/modulo data,
  transport corruption, final drain/ring accounting and runner failure evidence.
  Startup 8,704-symbol bus CRC is frozen at `0x6e67a0a0`; first-two-frame ring
  CRCs are `[89471290,752095060]` with 2,774 published groups and 4 pending symbols.
- Existing C3 parser tests execute the real new dispatch defaults, `best`, and
  explicit options. Full `make check` includes the older independent FEC,
  assembly semantics, PIO program and writer/clock tests.

The coordinator runner [b9_trial.py](../../host/b9_trial.py) reconstructs a finite
reference window around the absolute completed cursor. It independently builds
GCS → BB/BCH/LDPC → 8PSK/PL and directly evaluates the L7 integer FIR, without
using the firmware LUT or captured source ring as waveform truth. All 4,096
stride-17 samples must have one common global offset and match exactly, including
IQ_FLAG, unused low bits and GPIO28 phase. This is a sparse snapshot, not proof
of every output sample or RF performance. Final code-ring CRC verifies the
continuous packed stream independently of capture.

## Remaining risks and smallest follow-ups

The key unknown is simultaneous FEC/output arbitration. C8's 60-s CPU-only run
had 299.4k/318.7k worst frame work against 355.1k cycles, while B6 has only a
nominal two-cycle DMA row margin. Added IRQ work appears affordable by instruction
count, but neither that estimate nor native mocks proves timing. The high-priority
interrupt can still arrive late after masking/arbitration. A SOURCE_EMPTY or
capture mismatch is a failed B9 run even when the final encoded ring is correct.

If input IRQ latency alone fails, measure the masking interval and terminal FIFO
phase before changing the design. Four hardware reloads would require one fewer
concurrent channel elsewhere, or a different capture mechanism, to fit 16 DMA
channels. If frame work itself misses with clean grants, recover measured CPU
cycles or change placement using the recorded addresses; the three-table BCH
needs an additional wide table up to 120 KiB and does not fit this arena. Do not
claim 16 Msym/s by disabling the fault gate or replaying a published ring.
